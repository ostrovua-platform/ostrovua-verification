# Походження CoreML-моделі FaceEmbedding

- Файл: FaceEmbedding.mlpackage (не в репозиторії через розмір: 45M)
- Базова модель: FaceNet (конвертація: Tools/convert_face_model.py в основному проєкті)
- SHA-256 (усі файли пакета, відсортовані, конкатеновані):
  `04a4db780288799ebd2ee5ea79e5745ef25c7da03f1803ea4f9bb8585f5c4058`
- Перевірка на Маку:
  `find FaceEmbedding.mlpackage -type f | sort | xargs cat | shasum -a 256`

- Вхід моделі: image 160×160 (FaceNet), вихід — L2-нормалізований
  ембеддинг; косинус = скалярний добуток.

## Виміряна FAR/FRR (LFW, `Tools/FaceEval`, 2026-07-20)

Датасет: LFW 10-folds, funneled; препроцесинг дослівно як у застосунку
(Vision-вирівнювання + FaceEmbedder). Валідних пар: 2997 genuine +
2997 impostor (6 face-detect errors).

| Метрика | Значення |
|---|---|
| AUC | **0.9873** |
| EER | **3.37 %** (поріг cosine ≈ 0.320) |
| FAR @ старий поріг 0.60 | 0.0003 (0.03 %), FRR 14.1 % |
| **FAR @ обраний поріг 0.50** | **0.0013 (0.13 %), FRR 6.7 %** |

Витяг ROC (band FAR≈0.1–0.2 %):

| Поріг | FAR | FRR |
|---|---|---|
| 0.47 | 0.0017 | 0.056 |
| 0.50 | **0.0013** | **0.067** ← обрано |
| 0.54 | 0.0010 | 0.090 |
| 0.60 | 0.0007…0.0003 | 0.13…0.14 (старий) |

**Рішення:** `embeddingMatch` перекалібровано **0.60 → 0.50**
(`embeddingUncertain` 0.45 → 0.40). Обґрунтування: для привʼязки
особи до документа цільовий FAR ≈ 0.1 % — сильна точка; при цьому
хибне відхилення легітимних падає вдвічі (14 % → 6.7 %). LFW «в дикій
природі» складніша за наш сценарій (селфі ↔ фронтальне фото з чипа),
тож реальний FRR буде нижчим. Зафіксовано в `FaceMatcher.swift`.

Відкрите (чесно): іменований output tensor у коді береться як
`featureNames.first` — зафіксувати явно; доменна оцінка на власному
наборі селфі↔DG2 — окремий етап.
